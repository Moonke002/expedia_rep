# Part 1 design

## Frontend

Vue owns the “Choose stay” screen: hotel-name search, loading/error/empty states, supported city and nightly-price filters, and the repeated stay-card template. It sends the query to `/api/hotels/search`, renders returned hotel and stay fields, and calculates a stay total from nightly rate and fixed dates.

## FastAPI

FastAPI exposes `/api/hotels/search` and `/health`. The search endpoint validates the query and returns JSON records for matching hotels and stays. CORS permits the local Vue development server.

## Backend data

The backend reads `backend/hotels.csv` and `backend/trips.csv` on each search. It matches the hotel name, groups trips by `hotel_id`, and joins the matching records before returning them. CSV files are supplied data and are not generated by the application.

## Deliberate limits

The current CSVs contain no photos, ratings, amenities, flight inventory, savings, traveler accounts, saved state, or bookings. The frontend does not fabricate those values; it uses a CSS photo placeholder and labels savings as unavailable.
